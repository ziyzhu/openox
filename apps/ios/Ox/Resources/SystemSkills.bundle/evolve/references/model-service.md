# Model web services

The preferred website chat interface is one `conversation` Action with `submit`, `read`, and `cancel` operations. It serves ordinary service calls and model generation through the same website implementation. Adding the standard `listModels` Action makes that service available as a model provider. `conversation` alone is a service capability; `listModels` alone is not a model-provider declaration. There is no separate model-provider manifest field or service kind.

Use the web-service workflow for discovery, authoring, live verification, and Save. Built-ins remain read-only: copy to Local, resolve the existing service conflict, and edit the Local service. Provider and ordinary calls use the same selected source, but different owned pages and website conversations. Preserve unrelated Local edits. No automatic repair or task recovery is provided.

Read `skills/evolve/references/model-schemas.md` for exact schemas. Copy the standard schemas into the manifest Actions and provide the normal label, requireAuth, and requireApproval fields. Do not change the manifest format or standard schemas. Register one `conversation` handler; do not maintain separate website submission implementations or a provider/service mode argument. When an existing ordinary `listModels` uses another schema, preserve it as `listWebsiteModels` before adding standard model discovery.

Existing installed and Local services using `startModelGeneration`, optional `continueModelGeneration`, `readModelGeneration`, and `cancelModelGeneration` remain supported during the transition. Do not rewrite arbitrary user JavaScript, transfer standing approvals, or remove an existing ordinary chat Action without explicitly verifying its replacement. Converting a website requires a verified saved Local revision, not just new manifest schemas.

## Shared conversation contract

- The Host opens and retains an owned page. Provider ownership belongs to an Ox chat's provider context; service ownership belongs to its calling chat or Canvas; direct Client calls have a separate Host Client scope. These owners must not borrow one another's pages, conversation references, or submissions, even with the same website account. Keep website state in the page's installer closure, not shared between pages.
- `submit` receives `conversationRef: null` for a fresh website conversation, or a reference for continuation. `messages` is the input to submit **now**, not an instruction to replace remote history. Fresh provider turns contain the full serialized Ox context, including system instructions and Action envelopes. Provider continuations contain only new user/tool messages. Ordinary calls supply their explicit prompt/context; they do not inherit the provider's remote conversation.
- `accountId` is a website account/workspace/organization ID, or null to select the website's current/default account. Preserve explicit account selection from existing ordinary Actions, including Claude organization selection. The provider supplies null; resolve and bind the actual account inside the owned website driver. Reject ambiguous or unavailable account selections rather than silently choosing a different workspace. Account selection, model, and options cannot change during continuation.
- Reject unsupported models, options, and attachments before submission. Admit only one active submission per conversation. Do not queue, steer, or retry rejected input implicitly. Initiate one website submission, retain asynchronous work in the page, and return promptly. Report `submission: uncertain` unless acceptance is confirmed; an exception after possible acceptance must not trigger automatic resubmission.
- Return a page-local `submissionId` unique within that page and a stable page-local `conversationRef`. The Host rewrites both to process-local opaque handles and reverses that translation on later calls. Website handlers see only their own local IDs. Never treat a Host handle as a remote website ID or route read/cancel through a generic pooled page. Their runtime registry is not persisted or recoverable after process/page loss; handles in archived tool results cannot restore work.
- Return `continuation: true` only when the website driver can safely continue that conversation, including remote conversation/reply correlation. Continue only the latest completed, uncancelled submission; reject unknown, stale, busy, failed, and cancelled references. Continuation keeps model/options and accepts only new user/tool messages. Keep earlier submissions readable. Return the conversation reference consistently on every read.
- The provider Host continues only when the selected source, model, options, page, and complete prior Ox history still match. Edited/compacted history, changed system instructions, or a released page starts fresh with full context. A failed or uncertain continuation is surfaced without automatic resubmission.
- `read` receives `submissionId`, a zero-based `after` cursor, and a bounded wait of at most 1000 ms. Return events after that cursor and `nextCursor = after + events.length`. Each event advances the cursor once. Reads are repeatable, including after completion or later submissions; do not consume/delete events because they were read.
- Text events are full answer snapshots, not deltas. Published text grows by appending; do not emit provisional text that will be replaced. Emit exactly one completed or failed event, with no later events. Final-only websites return text then completed. Completion means a verified finished answer, not accepted input, stable DOM text, EOF, or a stopped animation. Classify failures as contextOverflow, rateLimited, network, authentication, unsupportedInput, or provider.
- Submit receipts and reads include the conversation URL when known (null otherwise), so callers can open pending work without waiting for completion. Completed events also carry the final URL and generated-file references, preserving IDs, names, kind, MIME type, size, thumbnails, dimensions, page/token counts, source, and downloadability. Use null for unknown metadata. File IDs identify website files, not local paths. File URLs can be session-bound; preserve the website's generated-file behavior for ordinary callers, but do not invent URLs, execute a URL as JavaScript, or automatically download from untrusted references.
- Return at most 1000 events per read. The Host bounds each submission to 4096 events and 2 MB of UTF-8 response text, and a page's retained answer text to 8 MB across at most 32 submissions. Keep website-side state similarly bounded. Published event identities and terminal outcomes must remain stable.
- `cancel` must remain callable while read waits. Report cancelled only when stopping is confirmed; otherwise requested, completed, or unsupported. A requested cancellation remains busy. Closing a page alone does not prove the remote work stopped. Never continue a cancelled conversation.
- `conversation` must be nonblocking and use one literal base URL. The Host retains at most 12 open/opening conversation pages. Idle nonbusy sessions expire after ten minutes when checked/pruned; active submissions have an absolute one-hour page lifetime, without claiming remote cancellation. Scope cleanup, source replacement, page interruption, failure, and memory pressure release owned pages and invalidate handles without resubmission.
- Native approval precedes submission/page creation. The manifest's approval policy applies to submit; read/cancel of an owned submission do not repeat approval. Authentication remains enforced through getSignInUrl/getSignInState and shared website storage. Do not ask for credentials in Action input.
- The Host stages attachment bytes as `File` objects in `window.__oxWebsiteFiles`. Each attachment's integer ID indexes that array; its name and MIME type must match the staged file. Use the real website upload flow, then clear temporary references. Ordinary chat calls resolve explicit Profile artifact names; Canvas and direct Clients cannot submit local attachment references. Do not request arbitrary local paths.
- `listModels` returns raw website model IDs, names, input modalities, known token limits or null, and supported options. Include `website-default` for the site's default. Do not add the Host's `website:` prefix. IDs/names must be nonempty and at most 100 characters; return at most 100 models, always including text input. Advertise streaming/cancellation truthfully and use positive known token limits.

## Legacy compatibility

Legacy model Actions retain their exact existing schemas. Start receives full messages, model/options, and attachments; optional continuation receives a previous generation ID, new user/tool messages, and attachments, keeping the prior model/options. Read/cancel use their generation ID on the same owned page. Their lifecycle, text/cursor, uncertainty, and cancellation guarantees remain unchanged. They are excluded from ordinary tool discovery, unlike `conversation`.

Legacy services without continuation use fresh website conversations with full Ox history each turn. Legacy services with continuation keep their page while the chat is attached and history remains compatible. Existing ordinary service Actions retain their own approval/execution rules. No stored manifest, installed source, saved provider selection, or approval is migrated merely because this contract was added.

## Verification

Verify both callers through actual service Actions. Browser exploration alone does not verify a handler. Exercise fresh provider and service submissions, concurrent same-account use, and at least two context-dependent turns in separate owned conversations. Verify model discovery, complete serialized Ox prompts and Action results, supported attachments, generated-file references, final-only/incremental output, and accurate cancellation while read waits. Confirm earlier receipts remain readable after continuation and each caller sees only its own context.

Test rejection of foreign-owner handles, unknown/stale/busy/failed/cancelled references, changed model/options/history, denied approval before submission, page loss, changed source, and uncertain acceptance without duplicate effects. Preserve sign-in data and saved model selections. Verify newly started work uses the edited Local source and there is still one provider entry for the service.

Fresh pages may use XHR where warm inspection pages use fetch; observe both. Confirm server-echoed prompts and matching remote conversation/reply identities, especially when long prompts are collapsed in the DOM. A service's old chat character cap is not evidence of a model context limit. Verify native editor state preserves the full prompt and report known context overflow.

Hidden pages may not run requestAnimationFrame. If site initialization depends on it, a service-local document-start timer fallback can keep callbacks running while hidden; preserve cancellation and execute each callback once. This must not submit again or bypass sign-in/human verification.

After page loss, report interruption; do not add background repair, durable checkpoints, fallback selection, or automatic resubmission.
