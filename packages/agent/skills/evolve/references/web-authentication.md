# Website Sessions and Login

A session is a currently authenticated website context, not an open page, remembered account, or Ox-created record. Preserve existing login state. Never sign out, clear website data, or repeat login solely for testing. Pages share the Host's existing persistent website data store; they do not isolate accounts.

## Standard actions

Authenticated web services implement both `listSessions` and `login`. Inspection advertises their Host access helpers instead of duplicating them in the business-action index; the implementations remain invokable for compatibility. Mark protected actions `requireAuth: true`; the Host resolves a descriptor through fresh account discovery instead of a generic boolean probe. Public actions use `requireAuth: false`. Session discovery and login require both `requireAuth: false` and `requireApproval: false`. The old getSignInUrl/getSignInState contract is unsupported.

`listSessions` takes a closed empty input object. Route tenant-specific discovery with top-level `pageUrl`; `session` independently selects account/context. Derive the actual target from the selected page; handlers do not receive the session descriptor. Its output schema is an array whose items are closed objects requiring string properties `id`, `label`, and `url`. Every value is nonempty. `id` identifies an authenticated account and its independent tenant scope, not a browser position, generic "current" placeholder, or token. `label` distinguishes accounts for the user. `url` is a public HTTPS entry point within the service domain identifying that context without credentials. It is validated metadata, not an action navigation override. Never include cookies, tokens, signatures, passwords, or reusable secrets.

Discover sessions using observed authoritative account selectors or authenticated endpoints. Website SDK authentication errors can trigger navigation, logout, or prompts; use observed request options that suppress those global effects during discovery without disabling authorization or server checks. Suppress SDK credential/header logging for identity requests. Return only currently authenticated contexts. A confirmed signed-out response returns `[]`; an unclassified status, remembered signed-out account, malformed response, CORS/network failure, or unsupported discovery must not be treated as an authenticated session or an empty list. Do not switch accounts or mutate user data during discovery. Multi-tenant discovery may require an employer or resource URL; do not claim a global directory exists when only one tenant was checked.

`login` accepts a closed empty object and returns `null` after preparing the interaction. Target routing uses the login action's `baseUrl` or top-level invocation `pageUrl`, not `session.url` or custom login parameters. Its handler can open dialogs, click account-selection controls, or navigate to an observed login route. Preserve tenant and resource return paths and all supported login options. Never guess a login path or accept credentials in arguments. The Host presents the same live page after preparation, waits for user completion, and preserves it. Cancellation throws. Completion acknowledges interaction only; subsequent defaulted invocations discover fresh sessions. Invoke `listSessions` afterward when choosing a specific account or tenant. There is no automatic detector or authentication polling.

Before returning from `login`, inspect the prepared live document and verify that the intended sign-in or account-selection controls are visible and usable for the requested product and tenant. Use a bounded wait for those specific controls, then throw a clear preparation error if they do not appear. A URL, navigation completion, page title, or generic nonblank page does not establish login readiness. Never return successfully from a blank, error, loading, or unrelated page: the Host presents immediately after the handler returns. Do not read or return credential field values.

## Execution

Invoke the website's standard `listSessions` and `login` actions through `ox.service.invoke`; both accept empty input and their full contracts are supplied upfront. Inspection lists standard-action availability without repeating schemas. For tenant discovery or login, optional top-level `pageUrl` selects an observed initial public HTTPS URL within the service domain. It is not an authenticated session. Stop capture and clear injected scripts before handing login to the user; never use Browser's generic interaction handoff for authentication.

When top-level `session` is omitted, ordinary invocations discover fresh sessions and use the first returned descriptor in the service's actual discovery order, including when `pageUrl` is provided. Initial discovery uses that observed target when supplied. This applies to public and protected actions. Discovery and login actions never auto-select. `session` selects account/context; `pageUrl` independently selects the initial navigation target within that context. Without sessions public actions stay public and protected actions fail before dispatch. Discovery failures or denied Action policies are errors, not empty lists. To choose a specific account or tenant, copy a returned descriptor into top-level `session`. Both `session` and `pageUrl` may be supplied. The Host validates the session entry URL and any `pageUrl`, but `session.url` never overrides navigation. Execution uses the action's input-resolved `baseUrl`, inherited from the service when omitted, unless `pageUrl` explicitly overrides it. Parameterize tenant/resource routes with declared action inputs; a tenant-specific discovery or login target uses `pageUrl`. The Host selects one live execution page for that session context; actions on it are serialized. Task arguments remain in `input`. Handlers are `async invoke(args)` and never receive the session descriptor. The Host selects the account, opens its page, and reruns read-only `listSessions` in that page before ordinary selected-session actions, rejecting a stale, missing, or altered descriptor before dispatch. Do not repeat that check in handlers. Check the account in a handler only when the page or an endpoint it calls might act as a different account than the page itself, such as multi-account sites that route by URL; compare it against discovery on that same page and reject mismatches without silently falling back to another account.

Explicit descriptors take precedence and are never replaced with the first available account if validation fails. Reuse an explicit descriptor to keep an account stable across actions; defaulted independent invocations follow fresh discovery order each time. Website conversation continuations pin their initial session and target. Do not add agent-side discovery before every invocation. For account-sensitive or consequential work, honor the user's intended account and target; discover and select explicitly or ask when that intent is ambiguous. Existing confirmation and Action approval requirements still apply. If access expires, discover again or request login rather than inventing a signed-out session. Shared cookies can change from another page. Never infer current authentication from a cached descriptor or cookie presence alone.

For review or takeover, use `ox.service.showPage` with the same action name, input, `session`, and `pageUrl` as the invocation, preserving omitted fields. It finds the latest matching recorded invocation's existing live page, including its actual defaulted session, without discovery, navigation, or replay. If the page was reused for another invocation or is unavailable, it fails rather than showing another account's document. Do not repeat a mutation if its original page is unavailable. Showing the page returns immediately and does not reserve it against subsequent actions. End the turn for human verification or payment; inspect fresh state after the user reports completion. Inspect uncertain mutations before retrying; never automatically repeat writes after login.

## Repair existing services

Treat an unsupported authentication contract as a normal service repair. Read the source even if the service cannot load, inspect current website evidence, and implement the standard actions above. Do not mechanically rename the old pair or invent account IDs from a boolean. Preserve unrelated Local edits, task contracts, and website data. Verify account-sensitive handlers act as the account their page discovers, validate the replacement, and reattach through the normal authoring workflow. No separate migration flow is needed.

API credentials, OAuth callbacks, and native OS permissions retain their existing contracts. Human verification and payment use ordinary service actions and ox.service.showPage; website login does not authorize payment or replace transaction review.
